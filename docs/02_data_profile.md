# 02 Data Profile

## Purpose

This document records profiling and quality results for the Open Food Facts dataset used in the Indonesia Food Product Landscape project.

The objective of profiling is to understand the structure, size, and key characteristics of the dataset before data quality assessment, relational modeling, and analytical work begin.

## Initial Structural Observations

The dataset contains a mixture of scalar fields, list-type fields, and nested structures.

Examples observed during initial profiling:

| Column | Type |
|----------|----------|
| code | VARCHAR |
| brands | VARCHAR |
| categories | VARCHAR |
| additives_n | INTEGER |
| completeness | FLOAT |
| brands_tags | VARCHAR[] |
| categories_tags | VARCHAR[] |
| countries_tags | VARCHAR[] |
| allergens_tags | VARCHAR[] |
| categories_properties | STRUCT |

Several fields contain arrays (`VARCHAR[]`) and nested structures (`STRUCT`), indicating that the source data contains implicit many-to-many relationships.

Potential examples include:

- Products ↔ Brands
- Products ↔ Categories
- Products ↔ Countries
- Products ↔ Allergens

These relationships may influence the final relational schema design.

## Candidate Product Identifier Assessment

### Field Evaluated

`code`

### Results

| Metric | Value |
|----------|----------|
| Total Records | 4,828,207 |
| Distinct Codes | 4,828,146 |
| Null Codes | 0 |
| Duplicate Code Groups | 61 |
| Rows Beyond First Occurrence | 61 |

### Observation

The `code` field has no missing values, but 61 codes occur twice. None of the 61 groups are exact duplicates across all 111 fields. In 52 groups, at least one product-description or assignment field differs: `brands_tags` (38 groups), `categories_tags` (36), `brands` (29), `quantity` (22), `product_name` (19), `packaging_tags` (13), `countries_tags` (6), or `packaging_text` (2). A group can differ in several fields.

### Interpretation

These repeated codes represent conflicting source records, not redundant rows that can safely be removed. All 61 pairs have distinct `last_modified_t` values, but choosing the later timestamp alone is not yet a validated deduplication rule; the conflict may affect product identity and analytical assignments.

### Decision

Do not use `code` as the primary key for the raw product-record table, and do not drop a row based only on duplicate code or modification time. Preserve both source records during staging; use a separate surrogate key for source rows. `code` may remain a candidate natural key for a curated product entity only after its source semantics and a documented conflict-resolution rule are validated.

The investigation is reproducible with `scripts/02_quality_checks.py`. Its row-level comparison evidence is in `outputs/quality/duplicate_code_investigation.csv`; the grouped duplicate counts remain in `outputs/quality/duplicate_codes.csv`.

### Interpretation and Limitations

- Brand tags and brand text are present for about 64% of records; category tags are present for about 40%, category text for about 28%, and food-group tags for about 31%. Cross-group comparisons must account for this uneven coverage.

- Brand/category value frequencies measure Open Food Facts record coverage, not market sales, market share, or a complete census of brands and products.
- Source duplicate codes were found to have conflicting records. These profiles remain record-based and do not deduplicate by `code`.

## Category Taxonomy Structure

The local Parquet includes category tags but not the category hierarchy field. The audit in `scripts/06_category_taxonomy_audit.py` compares observed values with the versioned taxonomy snapshot documented in [01_data_source.md](01_data_source.md).

| Metric | Result |
|----------|----------:|
| Taxonomy nodes in pinned snapshot | 14,774 |
| Distinct observed category tags | 116,105 |
| Exact matches in pinned taxonomy | 9,849 tags |
| Unmatched observed tags | 106,256 tags |
| Observed tag-record assignments matched | 9,935,298 of 10,480,049 (94.8020%) |
| Matched tags with multiple taxonomy depth paths | 4,469 |
| Assignments to tags with multiple depth paths | 2,134,785 |

The high assignment match rate alongside a low distinct-tag match rate means the unmatched values are mostly in the long tail; they must still be explicitly reviewed, excluded, or left unresolved rather than assumed to be aliases. The taxonomy is a directed graph, not a uniform tree: some nodes have multiple parent paths, and the dataset does not provide a single reliable numeric depth for every observed value. A hyphen count in a tag is not a taxonomy level.

An alternative source field, `food_groups_tags`, contains 56 observed values and 3,084,437 assignments across 1,519,234 records (31.4658% of all records). The reproducible profile is `outputs/profiling/food_group_tag_profile.csv`. It is a useful broad-group sensitivity check, but using it alone would omit about 68.5% of records and could introduce coverage bias.

### Recommended Analytical Grain

Preserve canonical taxonomy nodes and all parent-child edges in the relational model. Do not force a universal numeric hierarchy level. The approved reporting-group labels are recorded in `data/reference/category_reporting_group_framework.csv`: fruits and vegetables; cereals, potatoes and bakery; meat and poultry; fish and seafood; dairy and eggs; beverages; sweet foods and desserts; salty snacks; prepared meals; condiments, fats and spreads; and other/unclassified. `Other / unclassified` is approved as a diagnostic reconciliation bucket only and is excluded from primary comparisons unless its members are separately reviewed and assigned to substantive groups. Fifty-six exact-tag group decisions are now approved: 41 taxonomy-matched multi-group tags and 15 taxonomy-unmatched tags with exact supporting taxonomy tags. Remaining ambiguous and unmatched values stay unresolved unless a specific material analysis need warrants review. Retain legitimate multi-group assignments where approved and disclose overlap. Use `food_groups_tags` as a supplementary sensitivity check where its coverage is adequate, not as the sole category basis.

The reporting-group labels and diagnostic-only treatment of `Other / unclassified` are approved. The taxonomy-derived crosswalk remains a candidate, not a fully approved mapping: it inherits candidate groups only through exact taxonomy-node anchors listed in `data/mappings/category_reporting_group_anchor_candidates.csv`; it does not use text similarity. The 56 owner-approved exact-tag resolutions are recorded separately in `data/mappings/category_tag_reporting_group_manual_decisions.csv`. Their exact supporting tags and observed co-occurrence row counts are retained in `manual_evidence_tags` and `manual_evidence_cooccurrence_rows` in the crosswalk. For the 15 tags absent from the pinned taxonomy, this is a reporting-group assignment, not an alias or taxonomy-node claim. Other tags whose taxonomy ancestry reaches multiple groups remain unresolved; exact taxonomy matches without a domain anchor are residual `Other / unclassified` candidates for diagnostics only, and tags not found in the pinned taxonomy remain unmatched unless explicitly decided.

After the reviewed exclusions and manual decisions, the crosswalk classifies 7,889 observed tags (6,688,760 tag-record assignments) as single-group taxonomy candidates; 56 tags (387,144 assignments) as owner-approved manual group assignments; 841 tags (125,166 assignments) as unresolved multi-group candidates; 1,078 tags (2,797,475 assignments) as residual `Other / unclassified` candidates; 106,211 tags (425,398 assignments) as unresolved taxonomy mismatches; 29 tags (21,311 assignments) as excluded non-food; and one tag (34,795 assignments) as an excluded placeholder. Their respective shares of all category-tag assignments are 63.8237%, 3.6941%, 1.1943%, 26.6933%, 4.0591%, 0.2033%, and 0.3320%. These are summed source-tag frequencies, not distinct record coverage; one record can contribute several parent/child tags. The large residual share is diagnostic only and must not be treated as a substantive category for primary comparisons. The taxonomy audit's raw exact-match count remains unchanged: manual group decisions and exclusions are separate from taxonomy matches.

By candidate or approved manual group, summed tag-record assignments are: fruits and vegetables 538,538; cereals, potatoes and bakery 707,840; meat and poultry 756,142; fish and seafood 315,314; dairy and eggs 871,844; beverages 1,099,392; sweet foods and desserts 1,290,759; salty snacks 192,830; prepared meals 384,529; condiments, fats and spreads 918,716; and residual other/unclassified 2,797,475. These group figures are not mutually exclusive record counts; the reported tag frequencies can overlap across source records. Before category-level conclusions, review remaining multi-group tags, high-volume residuals, unmatched values, and actual record coverage by country. The pinned taxonomy is newer than the undated source snapshot and may not fully describe historical tags.

### Country-Level Candidate Coverage and Overlap

The script also evaluates reporting-group assignments at the source-record level, using only country tags approved in the maintained country mapping. A source row is counted once per ISO unit and once within each group; duplicate product codes are not deduplicated. Unresolved multi-group tags and tags absent from the pinned taxonomy are excluded from primary-group counts; approved manual decisions are included. The residual `Other / unclassified` count is reported separately for diagnostics and excluded from primary-group overlap calculations. One record can still belong to several primary groups, so group counts are not additive.

Across the 107 ISO units meeting the exploratory 1,000-source-record floor, median category-tag coverage was 33.4218% of country-assigned records. Among records with at least one category tag, the median with at least one primary candidate group was 84.4985%. Of records with primary group assignments, a median 14.2580% were assigned to more than one primary group. Group counts should therefore not be treated as mutually exclusive or added together.

For Indonesia, 1,111 of 9,118 country-assigned records had category tags (12.1847%); 788 of those had at least one primary group candidate (70.9271%). Of these 788 records, 132 (16.7513%) were assigned to more than one primary group. Separately, 651 records (58.5959% of Indonesia's category-tagged records) have at least one diagnostic residual tag for `Other / unclassified`; some may also have a primary-group assignment. This residual group is excluded from primary comparisons. These coverage levels and overlap are important comparability limitations, not final estimates of category prevalence. Script 07 outputs reflect the current mapping; the candidate-backed Stage 5/6 outputs provide the bounded country-level analysis and are documented in the analysis specification and Stage 7 findings.

### Non-Food Scope Audit

Scripts `09_nonfood_scope_audit.py` and `10_online_validation.py` extend the profiling evidence without changing the raw Parquet. Script 09 is deterministic and validates the Parquet row/column counts and pinned taxonomy checksum before writing outputs. It preserves tag values and case; dispositions are exact-match only. No records are deduplicated by `code`; rows and distinct codes are reported separately. Script 10 records retrieval dates and external evidence; its outputs are not expected to be byte-identical across runs.

#### Offline Record-Level Evidence

The offline audit assigns each row its strongest evidence class and retains the complete overlap matrix. ## Country Tag Mapping Review

The selected comparison scope is ISO 3166-1 units, including territories with ISO codes. Global, regional, supranational, and historical labels are excluded. Reviewed subnational labels are rolled up to their ISO 3166-1 parent and each record is counted once per resulting unit.

The maintained mapping is [data/mappings/country_tag_mapping.csv](../data/mappings/country_tag_mapping.csv). It contains one current decision per raw tag: approved, excluded, or requiring review. Approved codes are checked against the project's ISO alpha-2 reference snapshot in [data/reference/iso_3166_alpha2.csv](../data/reference/iso_3166_alpha2.csv); unresolved or ambiguous tags are not included in the normalized profile. The normalization script verifies that the mapping contains exactly the raw tag set present in the dataset. Tag frequencies are profiling results, not mapping attributes.

The original discovery-draft suggestions could not be recovered after a mapping-file truncation during the data reorganization. They are not represented as preserved audit data; the canonical file records only the current decisions and their rationale.

Tag-record assignments can overlap because a product can have multiple country tags. The eight tags requiring review account for 36 tag-record assignments; they include malformed or ambiguous values and have not been guessed into a country.

Remaining tags: `ru:nyl` (28 records), `en:North` (2), `ar:jorsan`, `bg:литвс`, `en:Indk`, `en:ser`, `en:عات`, and a malformed encoded Spain label (1 record each). They remain unresolved because the source values do not provide reliable enough evidence to map them safely.

The mapping has been reconstructed from the raw-tag inventory and the saved verified profile outputs. The source Parquet SHA-256 matches the previously recorded value, so the difference is not explained by a changed source snapshot. The saved profile differs by one Thailand record, and its approved/excluded tag-assignment totals differ by two. The original mapping and draft file are unavailable, and the remaining saved evidence contains only aggregates; it is insufficient to identify the exact historical tag-level decision behind the discrepancy. The reconstructed mapping is adopted as the reproducible working baseline for ongoing analysis, but it is not an exact restoration of the lost mapping. Keep the historical discrepancy visible and revisit it if an older mapping backup becomes available.
